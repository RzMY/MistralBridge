# 历史统计、日志保留与升降级

请求日志和历史统计分开存储。历史统计为默认首页，默认选择全部历史，展示总请求数和总 Token 趋势；一天以内（含完整自然日）按小时展示。日志页仅展示筛选后的明细。删除明细不会减少已累计的用量。

## 统计口径

- 每次插件执行完成记一条，成功和失败都计数。CPA 重试产生多次插件执行，分别累计；这不是客户端去重后的会话数。
- 日汇总按请求开始时间的 **UTC 自然日**归属；没有时间的旧记录进入“日期未知”，只参与不限日期的查询。
- 可组合筛选请求模型、上游模型、凭证 ID、思考强度和结果。凭证改名、删除不会删除历史汇总。显示名称仅供辨认，ID 才是归属依据。
- 保存请求数、成功/失败数、输入/输出/总 Token、缓存用量和有效样本的累加量。缓存率及生成速率沿用日志页的样本条件，跨日汇总从分子、分母重新计算。
- 缺少用量的请求单独计数，不把零用量推断成准确的消耗。旧日志含非零 Token 时沿用已有信息。
- 平均耗时按全部执行记录计算。生成速率只包括成功、有首字时间且生成耗时大于零的流式记录。平均首字只包括有非负首字时间的成功流式记录，保存首字总耗时与样本数，合并时重新加权。旧版缺少此字段时，只有保留日志能够完整核对对应汇总桶才补齐，否则显示已有有效样本或 `—`。
- 明细按时段显示缓存命中率、Token 速率、平均首字、平均耗时。只展示请求数大于零且开始时间不晚于服务器当前时间的时段；标签不显示 UTC 偏移，内部仍使用完整时间戳区分夏令时重复小时。

图表跟随筛选条件。请求和 Token 各只显示一个总量序列，不再拆分成功/失败或输入/输出。较长日级区间合并为最多 60 个等长时间段，悬停或键盘聚焦可查看具体数值。

统计首页默认“全部历史”，另有今天、昨天、近 7/30 天及自定义起止时间。快捷日期由**浏览器的系统时钟与本地时区**计算；请求时间戳由 **CPA 服务器系统时钟**生成。浏览器发送明确起止时间和 IANA 时区，后端不依赖服务器默认时区划分日期。修改设备时区会改变日期边界；设备或服务器时钟不准确也会影响显示。夏令时自然日可能为 23/25 小时，仍按分时展示。

新增分钟汇总保留最近 90 天，以支持半小时/四分之一小时时区和分钟级自定义区间。原有 UTC 日汇总永久保存，不改变旧接口字段。清空日志不删除分钟汇总；清空统计同时重置两种汇总。第一次使用或旧版写回丢失新增字段后，从仍保留且可确认已计入日汇总的日志重建分钟数据，不重复累计日汇总。已删除明细或超过 90 天的分时分布无法恢复；无法确定本地日期的旧日汇总只保留在完整累计和“未分时历史”，不猜测小时分布。缺少分时数据会通过请求数悬停详情和 `timeline_partial` 标明。

旧客户端的 `from_day/to_day` 接口仍按 UTC 日汇总。新版使用 `from/to`（RFC3339，按分钟对齐，结束不包含）、`timezone`（IANA）与 `granularity=auto|hour|day`，响应 `series` 含时段起止、显示标签及总量。没有起止范围时返回全部累计；部分区间无法确定的历史不混入确定值。

## 保留规则

默认明细最多 **10,000 条、30 天、32 MiB**，三个限制同时生效。可在请求日志第二行的保留设置（默认展示当前值，点击“编辑”后输入并保存；取消恢复原值）调整为 1–10,000 条、1–3650 天、1–256 MiB。触及数量或容量限制时分批清理，通常留出约 10% 空间，减少整文件重写；实际条数可以低于上限。最近按完成顺序写入的记录优先保留，过期判断使用请求开始时间。

启动、写入请求、读取日志、修改保留设置时执行清理。空闲时不定时唤醒磁盘；没有新写入时文件也不会继续增长。容量限制针对保留后的 `requests.jsonl`，写入和同目录替换过程中需要临时空间。调试明细仍独立限制为最近 100 条、总计 256 MiB。

历史日汇总长期保存，会随日期和实际维度组合缓慢增长；它不保存提示词、响应正文、错误正文或每次请求的永久 ID 集合。不能同时承诺永久任意维度查询和整个目录固定容量。

## 文件与恢复

所有文件使用现有 `statePath()` 解析的数据目录，不更改凭证、模型或 CPA ABI：

| 文件 | 用途 |
| --- | --- |
| `state.json` | 原有配置，不嵌入历史统计或新版保留设置 |
| `requests.jsonl` | 保持旧版 `RequestLog` JSONL 格式的有限明细 |
| `telemetry/config.json` | 独立版本号的保留设置 |
| `telemetry/snapshot.json` | 日汇总、统计周期、完整性状态、序号及有限去重信息 |
| `telemetry/journal.jsonl` | 已同步到文件、尚未合并的记账事件，正常运行最多 8 MiB |

完成请求后先写 journal 并调用文件同步，再更新汇总和兼容日志。每 128 条、journal 即将达到容量上限、清理明细或退出时生成快照。快照通过同目录临时文件、文件同步及替换发布，之后才回收 journal。崩溃后按序号重放，必要时恢复兼容日志。只能承诺已成功持久化事件的恢复；模型响应已到达但尚未记账就断电、磁盘故障等情况无法凭空恢复。

完整但损坏的 journal、未知快照版本、未知设置版本会返回统计不可用并保留原文件。未完成的 journal 尾行在验证其他事件后丢弃，标记历史可能不完整。存储异常不会把成功模型响应改成失败；宿主进程日志会记录错误，管理页显示统计故障，普通日志采用有界的兼容回退。

清空明细先持久化清理意图，防止中断后恢复已清除记录。重置统计创建新周期，但保留已处理序号和仍存在日志的 ID，防止旧明细在重启后重新累计。备份及恢复应以整个插件数据目录为单位；不要手动拼接来自不同备份的统计与日志文件。单个数据目录由一个插件实例写入，升降级应停止原实例再启动另一版本。

## 升降级边界

首次升级扫描磁盘上全部有效日志，再应用新版保留规则；不经过只返回最后 10,000 条的旧读取函数。已被旧版删除的历史不可恢复，请求数的悬停信息提供“升级前仅导入仍存在的日志”等完整性详情。日志损坏或缺少时间也会记入完整性状态。

降回 v0.5.0 后，凭证、模型和请求日志仍可使用；旧版不更新或删除 `telemetry/`，也不会执行新版自定义保留规则。重新升级时，先恢复 journal，再根据现有请求 ID 与上次兼容日志末尾记录识别追加内容，补入可以确认的新记录。

如果旧版已删除全部衔接记录，就无法区分“旧版运行产生的新文件”和“恢复的旧备份”。此时保留已有累计，将无法确认的日志标记为未自动补计；不猜测缺失请求数，也不重新累计整份文件。完整性提示是保守的，可能包含外部清理或中断维护导致的不确定性。再次重启不会反复补入同一批记录。

旧版清空日志不会删除独立统计文件。新版清空明细与重置统计是不同操作。兼容性保证针对新增统计功能与 v0.5.0 的往返；更早版本自身不认识的凭证、代理等配置，不属于本次改造能补足的兼容范围。

## 管理接口

以下路径相对于 `/v0/management/plugins/mistral-bridge`，复用现有管理认证。

| 方法和路径 | 行为 |
| --- | --- |
| `GET /state` | 增加 `capabilities.historical_stats=true`、`time_series_stats=true` |
| `GET /logs` | 保留原有字段和筛选语义，增加保留策略、实际时间范围、存储错误信息 |
| `GET /stats` | 兼容日查询返回 `daily`；本地时区查询返回 `series`，均包含统计、周期及完整性状态 |
| `GET /telemetry/settings` | 获取 `version`、`max_entries`、`max_days`、`max_bytes` |
| `PATCH /telemetry/settings` | 部分更新保留设置，并清理超限明细 |
| `DELETE /logs` | 清空请求及调试明细，保留历史统计 |
| `DELETE /stats` | 重置历史统计周期，保留明细 |

`GET /stats` 支持 `from_day`、`to_day`、`model`、`upstream_model`、`key_id`、`thinking`、`status`。日期格式为 `YYYY-MM-DD`。`incomplete_reasons` 提供升级前历史未知、旧版日志不连续、无法安全补计、日志损坏、缺少时间或写入失败等原因。降级后仍打开的新版页面会提示历史统计不可用，引导回原日志页。

## 验证

Go 测试覆盖超 10,000 条迁移、字节/天数/数量限额、重启幂等、并发累计、加权指标、清理及重置、写入失败、未知格式保护和 journal 恢复。

真实动态库往返检查使用独立子进程和临时数据，验证旧版追加、超过 16 MiB 的实际日志压缩、配置保存、日志清空及重复再升级：

```sh
python scripts/check_telemetry_upgrade.py /path/to/new-library /path/to/v0.5.0-library
```

两个动态库必须匹配运行检查的操作系统和架构。检查不访问真实上游，不使用用户凭证。

在 Linux 服务器上可另外运行真实 CPA 容器集成检查。脚本创建独立数据目录及仅监听回环的模拟上游，验证普通/流式/失败请求、迁移、保留限额、清空、重置及重启，不读取用户凭证：

```sh
python3 scripts/check_telemetry_cpa.py --library /path/to/mistral-bridge.so \
  --version 0.5.1-telemetry-test --image eceasy/cli-proxy-api:v8.0.78 \
  --work-dir /path/to/new-test-directory
```

C ABI 往返测试通过子进程启动环境传递数据目录；Linux 的 Go 动态库初始化可能在 `ctypes.CDLL()` 前捕获进程环境，不能仅在 worker 内修改 Python 的 `os.environ`。
